## Coordination alerts (to Hermes)

### 🔴 P1 — The rebase queue cannot drain: epic label inheritance blocks the coder loop

`bd create --parent caro-jac` **copies the epic's labels onto the child at
creation time**, including `claim_policy:manual_only`. Verified empirically
this cycle: the label was written to the child's own record (removing it from
`caro-jac.102` persisted, so this is stored state, not display-time merging).

Effect: **38 of 46** `caro-jac.N` rebase beads that should be claimable by
`/caro-coder-loop` are gated `manual_only` and will never be picked up.

Cross-tab of rebase beads by parentage:

| parentage | path label | manual_only | count | correct? |
|---|---|---|---|---|
| standalone (`caro-xxxx`) | path:deep | true | 3 | ✅ |
| standalone | path:auto / path:scoped | false | 3 | ✅ |
| child (`caro-jac.N`) | path:auto | true | 18 | ❌ |
| child | path:scoped | true | 14 | ❌ |
| child | path:auto,path:scoped | true | 6 | ❌ |
| child | path:deep (+scoped) | true | 8 | ✅ (deep is manual by design) |

Standalone beads behave correctly — `manual_only` tracks `path:deep` exactly.
Only the epic-parented ones are wrong. This explains why the queue has sat at
steady state for weeks: the dispatcher files beads correctly and the coder
loop correctly finds nothing claimable.

**Remediation** (not executed — bulk write outside this routine's dispatch
mandate; needs a human or an explicitly-scoped run):

```bash
bd list --limit 3000 --json </dev/null \
  | jq -r '.[] | select((.external_ref//"")|test("^gh-.*-rebase$"))
           | select((.labels//[]|index("claim_policy:manual_only")) != null)
           | select((.labels//[]|index("path:deep")) == null)
           | .id' \
  | while read id; do bd label remove "$id" claim_policy:manual_only </dev/null; done
```

The `select(path:deep == null)` clause preserves manual-only on the 8 beads
where it is correct.

**Root-cause fix** belongs in the dispatcher: either stop passing `--parent
caro-jac` and use a dependency edge instead, or strip inherited labels
immediately after `bd create`. Filing this as a follow-up is recommended.
