# How agent harnesses decide to auto-approve shell commands (state as of 2026-10-11)

> **Corrections, 2026-10-13** (PR #1583 review and owner-supplied sources). Inline text below is corrected where marked. Where this note and the corrections disagree, the corrections win.
>
> - **Claude Code** also ships built-in protections against removing critical paths, and a mod surface (`tool.check`) that can approve a call before the classifier runs. PreToolUse hooks and mods have different authority. Do not claim that Claude Code lacks curated checks, or that anything is universally non-overridable. Sources: https://code.claude.com/docs/en/permission-modes ; https://code.claude.com/docs/en/permissions#extend-permissions-with-hooks
> - **Codex**: the custom-provider Auto-review failure is an operational bug with workarounds (openai/codex#31255), not model lock-in.
> - **Default-on vs available**: see the corrected headline findings 1 and 2.

Research for Caro's "cross-harness auto mode engine" positioning. All pages fetched 2026-10-11 unless a date is given.
Legend: **[V]** = verified on a primary page in this session. **[S]** = secondary source only. **[U]** = could not verify.

## Headline findings

1. Many harnesses now offer an LLM-judged auto mode, but only some turn it on by default (corrected 2026-10-13, thread T16):
   - On by default: Claude Code (classifier; default starting mode from v2.1.283) and Cursor (Auto-review; default since 3.6).
   - Available, not default: Codex Auto-review ("guardian") needs `approvals_reviewer = "auto_review"`; VS Code defaults to Manual
     (Assisted permissions is experimental); Grok Build and Qwen Code default to Ask; Windsurf/Devin Desktop and goose Smart Approve are opt-in modes.
2. Some built-in judges are tied to their vendor's models or backend (corrected 2026-10-13, thread T15):
   - Claude Code auto mode needs a supported Claude model. Cursor's classifier runs on Cursor's backend.
   - Codex Auto-review failed on custom providers because of a hardcoded `codex-auto-review` model name. This is an operational bug with
     model-catalog and gateway workarounds (openai/codex#31255; https://learn.chatgpt.com/docs/sandboxing/auto-review), not inherent lock-in.
   - goose Smart Approve uses the user's own configured provider, so it is provider-agnostic.
3. There is no cross-harness policy standard. There IS de facto convergence on the Claude Code `PreToolUse` hook shape
   (stdin JSON with `tool_name`/`tool_input`; stdout `permissionDecision`; exit 2 = block). Copilot, Cursor, Grok Build and VS Code even read `.claude/settings.json` hooks directly.
4. Two free, popular, multi-harness deterministic guards already exist: **dcg** (Rust, ~6.1k stars) and **cc-safety-net** (MIT, ~1.6k stars, 15+ CLIs on 2026-10-11; 16 harnesses per its README on 2026-10-13).
5. Vendors and researchers agree that neither a classifier nor a regex list is a security boundary. The OS sandbox and egress control are.

## Cross-harness integration points

### Hooks: de facto convergence on the Claude Code shape (no formal standard)

```
                 ┌─────────────── Claude-shaped PreToolUse (stdin JSON → stdout permissionDecision / exit 2) ───────────────┐
 native:         Claude Code · Codex (allow/deny only) · Factory Droid · Copilot CLI · VS Code · Qwen Code · Kiro
 reads .claude/  Copilot CLI · VS Code · Cursor ("third-party hooks") · Grok Build (+ .cursor/hooks.json)
 own dialect:    Cursor beforeShellExecution {permission} · Gemini CLI BeforeTool {decision:deny} · Antigravity PreToolUse {decision,...}
                 Windsurf pre_run_command (exit 2) · Cline PreToolUse {cancel} · Amp plugins / delegate helper · OpenCode tool.execute.before
```

- **Allow-capable** (a hook can grant approval, not only veto): Claude Code, Codex, Copilot CLI, Factory, Cursor, Antigravity.
- **Veto-only** (documented decisions are block/deny): Gemini CLI, Grok Build, Windsurf/Devin, Cline, Kiro.
- Even where "allow" exists, it does not always win. Claude Code still applies deny/ask rules and critical-path guards after a hook "allow". Codex applies its OS sandbox regardless.
- No vendor-neutral hooks spec was found. A secondary source says "five out of six major platforms" support lifecycle hooks with differing event names.

### Agent Client Protocol (ACP)

- `session/request_permission` (agent → client) carries the tool call and options `allow_once` / `allow_always` / `reject_once` / `reject_always`. "Clients MAY automatically allow or reject permission requests according to the user settings." [V] (agentclientprotocol.com/protocol/tool-calls, protocol v1)
- ACP Registry launched 2026-01-28 with Claude Code, Codex CLI, Copilot CLI, Gemini CLI, Factory Droid, Mistral Vibe, Qwen Code, OpenCode, Auggie and others [S] (zed.dev/blog/acp-registry; heise.de). Kimi CLI ships `kimi acp` [V].
- This is the one protocol-level choke point where a single decider can serve many agents, but only when the agent is driven by an ACP client (Zed, JetBrains). A forum report says Cursor's ACP mode ignores its own auto-review [S].

### Other standards

- **MCP**: tool connectivity, not command policy. Only per-tool annotations (e.g. Claude Code honors `requiresUserInteraction`). [V]
- **AGENTS.md / CLAUDE.md**: shape model behavior, not enforcement ("Permission rules are enforced by Claude Code, not by the model"). Note: Claude Code's classifier reads CLAUDE.md, so instruction files do steer that judge. [V]
- **Agent policy spec**: none found. The Agentic AI Foundation hosts MCP, AGENTS.md, goose, A2A (Aug 2026) and agentgateway; no permissions spec [S].
- **OpenTelemetry GenAI**: `execute_tool` spans exist; conventions moved to `open-telemetry/semantic-conventions-genai`, status Development [S]. No approval-decision attribute verified [U].

## Implications for Caro as a cross-harness auto-mode engine

> Caveat (per `validation-discipline.md`): this is desk research about competitors. It is not user validation and clears none of the five gates.

### Where the gap is

1. **BYO-model users have no auto mode.** Claude Code auto mode needs a supported Claude model. Codex Auto-review fails on non-OpenAI providers (DeepSeek error in #25395). Cursor's classifier is Cursor-hosted. Harnesses built for any model (OpenCode, Crush, Aider, Cline, Roo, Zed, Mistral Vibe, Kimi) have either no judge or only model self-assessment (Cline `requires_approval`, Windsurf "Auto"). A **local**, model-agnostic second-stage judge behind deterministic rules is the thing nobody ships cross-harness. This is Caro's clearest opening.
2. **Policy is not portable.** Eight incompatible formats: Claude prose `autoMode`, Codex `policy.md` + Starlark `.rules`, Cursor prose `permissions.json`, Gemini TOML, Antigravity `action(target)`, Kiro YAML, Zed regex, Copilot flags. One user-owned policy compiled into each harness's hook dialect is unserved (dcg's per-agent profiles come closest).
3. **Determinism and audit.** Vendor judges are non-deterministic and can change server-side ("A classifier model that Anthropic configures server-side takes precedence"). Error rates are material: Anthropic reports 17% false-negative rate on real overeager actions; OpenAI 90.3% overeagerness recall. Enterprises that need reproducible, logged decisions (OTel) have no neutral option.
4. **Privacy.** Built-in judges send transcript slices to the vendor (Claude: user messages + tool calls; Codex: also tool outputs; Cursor: request + file reads to Cursor's backend, judged by Google/Anthropic models).

### Who already covers it

- **Inside each frontier harness:** on-by-default, intent-aware LLM judges (Claude Code, Cursor, Codex, VS Code, Grok, Qwen).
- **Cross-harness deterministic layer:** dcg (source-available) and cc-safety-net (MIT) already install into many harnesses (17+ and 16, per their READMEs). Caro would enter third into the "destructive-command regex" niche.
- **Hard boundary:** OS sandboxes (Codex default-on; Claude Code `srt`; Cursor; Antigravity).

### Strongest counter-argument (why a user might not need Caro)

A Claude Code or Cursor user already has a free judge that is on by default and sees user intent (Codex, VS Code, Grok and Qwen users must opt in; corrected 2026-10-13), was tuned on real traffic (Anthropic: 0.4% false-positive rate for the full pipeline), and runs inside the harness with no install. The residual risks that matter most (prompt-injection chains, exfiltration, scope creep) depend on intent and context, which a stateless regex over one command cannot see. Rehberger's Aug 2026 chain beat Claude auto mode 60–80% of the time, and the fix everyone recommends is a sandbox and egress control, not a better list. Anthropic and Cursor both say their judges are "not a security boundary". Deterministic parsers are themselves bypassable: Roo Code CVE-2026-82536/82537 and Cursor CVE-2026-22708 are exactly the allowlist-parsing class that a regex engine invites. The deterministic niche is already served by MIT/permissive tools with wider harness coverage, while Caro is AGPL-3.0, which deters corporate hook deployment. Finally, in veto-only harnesses (Gemini CLI, Grok, Windsurf, Kiro, Cline) and even in Claude Code (deny/ask rules still apply after a hook "allow"), an external hook can only add denials. It cannot fully replace the native approval flow, so "auto mode engine" overstates what the integration point allows.

### What would make the position defensible (for the owner to decide)

1. Target BYO-model and local-model setups first, where no vendor judge works.
2. Ship one policy file that compiles to every hook dialect, plus an ACP client-side decider.
3. Use a real shell parser, not regex-only matching, to avoid the Roo/Cursor bypass classes.
4. Publish false-positive and false-negative rates on a shared benchmark against cc-safety-net and vendor judges (dcg excluded pending a human license decision; corrected 2026-10-13).
5. Emit decisions as OTel events for audit.
