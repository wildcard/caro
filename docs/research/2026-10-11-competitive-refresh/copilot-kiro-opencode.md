# Competitive fact-check: GitHub Copilot CLI, Kiro CLI, OpenCode (as of 2026-10-11)

> **Corrections, 2026-10-13** (PR #1583 review and owner-supplied sources). Where this note and the corrections disagree, the corrections win.
>
> - **Copilot offline** needs a local model **and** `COPILOT_OFFLINE=true`; a hosted BYOK endpoint still needs the network (https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models).
> - **Copilot local-model discovery** (https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/) finds local models you already run. It installs no runtime or model and does not turn on offline mode. Intelligent routing is described as future work.
> - **Copilot sandbox default:** the GA changelog (2026-10-07) does not say whether it is on or off by default. Treat the default as unknown.
> - **Copilot CLI `assisted` mode:** the official CLI reference confirms only the mode name; whether it uses a model judge is undocumented. The documented LLM judge belongs to VS Code Copilot Chat's separate **Assisted permissions** mode (experimental); do not carry it over to the CLI.
> - **OpenCode defaults** (permissions page, updated 2026-10-13): most operations allow; `doom_loop` and `external_directory` ask; `.env` reads deny, with an `.env.example` exception.

**Needs you:** Several website cells are out of date. The largest errors:

1. **Copilot "Works 100% offline = no"** is wrong since 2026-04-07. BYOK, local models (Ollama/vLLM/Foundry Local) and `COPILOT_OFFLINE=true` shipped. GitHub auth is not required in BYOK mode.
2. **Copilot "Full source = partial"** is wrong. `github/copilot-cli` has no source code. LICENSE.md is a proprietary "GitHub Copilot CLI License" that forbids modification. It should be **no**.
3. **Copilot pricing "$10-19/month"** is wrong. Copilot Free ($0) includes the CLI. Paid tiers are now Pro $10, Pro+ $39, Max $100, Business $19/seat, Enterprise $39/seat, with usage-based "AI Credits" since 2026-06-01.
4. **"Customizable safety rules = no"** is wrong for **all three**. Each one has deterministic, user-authored allow/ask/deny rules for shell commands and a pre-tool hook that can block a command.
5. **OpenCode "Explicit confirmation = partial"** is generous. By default OpenCode "allows all operations without requiring explicit approval". It should be **no by default (opt-in `ask`)**.
6. **Copilot "Multi-backend = no"** is outdated. It offers Anthropic/OpenAI/Google models plus BYOK for any OpenAI-compatible endpoint. Use **yes**, or **partial** if you count only GitHub-hosted models.

What the docs show for all three (scoped 2026-10-13): **by default none of them blocks `rm -rf /`.** Copilot CLI and Kiro CLI document asking before such commands; OpenCode's documented defaults allow shell commands. Their documented controls are prompting, user-written rules and sandboxing. None of their docs describes a built-in library of destructive-command patterns. That is not proof that no library exists: Copilot CLI and Kiro CLI are closed source, so the source ledger marks their library and risk levels "unknown", not "no". Whether Copilot CLI's `assisted` mode uses a model judge is undocumented; VS Code's separate Assisted permissions mode does. The documented difference is Caro's default: 52+ bundled patterns that block Critical commands with no configuration. Whether those patterns catch more than the competitors' controls is unmeasured (strategy note, test 1). "Customizable" and "rule-based" are not differentiators.

Website files that carry these claims: `website/src/pages/compare/index.astro`, `website/src/pages/[lang]/compare/index.astro`, `website/src/pages/compare/github-copilot-cli.astro` (line 53 has "$10-19/month"), `website/src/config/search-index.json` (line 2400), `website/src/i18n/locales/*/landing.json`.

Confidence: High = primary source fetched today. Med = primary source seen in search only, or primary source is ambiguous. Low = third-party only.

### Copilot CLI: hook points for an external validator such as Caro

- **Events:** `preToolUse` (blocks; camelCase payload `toolName`, `toolArgs`) and `PreToolUse` (VS Code-compatible snake_case payload `tool_name`, `tool_input`). `permissionRequest` is CLI-only. It fires *before* rule checks, session approvals and the user prompt, and returns `behavior: allow|deny`, `message`, `interrupt`. Others: `postToolUse`, `postToolUseFailure`, `sessionStart`, `sessionEnd`, `userPromptSubmitted`, `userPromptTransformed`, `agentStop`, `subagentStart`, `subagentStop`, `preCompact`, `errorOccurred`, `notification`.
- **Config locations (all merged):**
  - `.github/hooks/*.json` (repo)
  - `~/.copilot/hooks/*.json` (user; Windows `%USERPROFILE%\.copilot\hooks\`; or `$COPILOT_HOME/hooks/`)
  - inline `hooks` blocks in `.github/copilot/settings.json`, `.github/copilot/settings.local.json`, `~/.copilot/settings.json`, **and `.claude/settings.json` / `.claude/settings.local.json`**
  - admin policy `/etc/github-copilot/policy.d/*.json` (Windows `C:\ProgramData\GitHub\Copilot\policy.d\` or the HKLM registry)
  - plugin `hooks.json`
- **Schema:** `{ "version": 1, "hooks": { "preToolUse": [ { "type": "command", "bash": "...", "powershell": "...", "timeoutSec": 30, "matcher": "<regex>" } ] } }`. An HTTP hook (`type: "http"`, `https://` only) is also supported.
- **Deny semantics:** stdout JSON `permissionDecision: "allow"|"deny"|"ask"`, plus `permissionDecisionReason` (required on deny). `modifiedArgs` can rewrite the call. **Exit 2 = deny.** Other non-zero exits also deny (fail-closed). **Timeouts fail open** (default 30 s), and HTTP errors fail open.
- **Gap:** the docs type `toolArgs` as `unknown`. The field that carries the shell command text is **not documented**, so it is unverified.
- **Static rules** do not need a hook: `--deny-tool 'shell(rm)'`.

### Kiro CLI: hook points for an external validator

- **V3 (current, opt-in) hooks:**
  - Standalone files go in workspace `.kiro/hooks/<id>.json` and global `~/.kiro/hooks/` (global is V3 only). Agent profiles can also carry a flat `hooks` array.
  - Schema: `{ "version": "v1", "hooks": [ { "name", "trigger": "PreToolUse", "matcher": "<tool id | category tag | @mcp | @server | regex>", "action": { "type": "command", "command": "..." }, "timeout": 60 } ] }`. Default timeout is 60 s, and `0` disables it.
  - Triggers: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SessionEnd` (added in 2.25.0) and `PostFileSave`. Since 2.28.0, V3 hooks can match by tool category.
- **2.x / Classic hooks:**
  - Defined in the agent config `hooks` field with camelCase triggers `agentSpawn`, `userPromptSubmit`, `preToolUse`, `postToolUse`, `stop`.
  - Matcher by tool name, for example `execute_bash` / `shell`.
- **Block semantics:**
  - **Exit 2 blocks `PreToolUse`**, and STDERR returns to the agent.
  - Other non-zero exits warn and still allow the tool (fail-open).
  - stdin is JSON session context. The V2-engine tool hooks get `tool_name` and `tool_input` (plus `tool_tags`). The exact field that holds the command text in V3 is **not documented** (unverified).
- **Static rules without a hook:** use `permissions.yaml` with `capability: shell`, `effect: deny`. Managed `managed-settings.json` gives org-wide enforcement.

### OpenCode: hook points for an external validator

- **Plugins (JS/TS):**
  - Locations: project `.opencode/plugins/`, global `~/.config/opencode/plugins/`, or npm packages listed in the `"plugin"` array of `opencode.json`.
  - Hook `tool.execute.before(input, output)`: `input.tool === "bash"`, and `output.args.command` holds the command text. The docs show it being read and rewritten. **`throw new Error(...)` blocks the call** (the docs' `.env` example).
  - Other hooks: `tool.execute.after`, `shell.env`, events `permission.asked` / `permission.replied`, `session.idle`, `file.edited`.
- **Static rules:** `opencode.json` → `"permission": { "bash": { "*": "ask", "rm *": "deny" } }`, per-agent `permission`, or env `OPENCODE_PERMISSION='{"bash":...}'`.
- OpenCode also reads `.claude/` skills and `~/.claude/CLAUDE.md` by default (`OPENCODE_DISABLE_CLAUDE_CODE*` turns this off).

## Cross-product notes for Caro positioning

- **Deterministic vs model-judged:**
  - All three products use deterministic matching for *user-written* rules: Copilot `shell(cmd)` patterns, Kiro glob (V3) or regex (2.x), OpenCode wildcards.
  - None ships a curated, risk-graded destructive-command library on by default.
  - How Copilot decides a shell command is "read-only" is undocumented.
  - Copilot CLI's `assisted` permission mode: the official reference confirms only the mode name. No CLI-specific source says it is model-judged. (VS Code Copilot Chat's separate Assisted permissions mode is documented as an LLM judge.)
- **One Caro validator could plug into all three:**
  - A single `caro`-style validator command could act as Copilot `preToolUse` (exit 2 or `permissionDecision: deny`), Kiro `PreToolUse` (exit 2 + stderr) and an OpenCode `tool.execute.before` plugin (throw).
  - Copilot also loads hooks from `.claude/settings.json`.
  - Fail-mode differences matter: Copilot fails **closed** on non-zero exit but **open** on timeout. Kiro fails **open** on non-2 exits.
- **Sandboxing is now the vendor answer:**
  - Copilot local sandbox went GA on 2026-10-07.
  - Kiro Web uses a sandbox.
  - Expect "OS sandbox" to appear in competitor matrices. Caro's pre-execution validation complements a sandbox; it does not replace one.
