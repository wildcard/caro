## Summary (read this first)

1. **Two command guards lead the "cross-harness command guard" slot today** (corrected 2026-10-13, thread T8). `dcg` (Rust, 6,139 stars, 17+ harnesses) is **source-available**: MIT text plus a rider that grants no rights to OpenAI, Anthropic, their affiliates or anyone acting for them, and that defines "use" to include benchmarking, testing and analyzing. `cc-safety-net` (TypeScript, 1,583 stars) is **MIT**; on 2026-10-13 its README lists 16 harnesses, parsed-command handling, secret protection and cloud/IaC rulebooks, and its known-limitations page names incomplete event coverage and fail-open hosts (https://ccsafetynet.com/docs/guides/known-limitations). Both are deterministic, local and hook-based. That is Caro's proposed position. Do not execute, benchmark or import dcg; compare it from its public docs only, pending a human license review.
2. **Several major harnesses now ship an LLM auto-approver** (corrected 2026-10-13, thread T26). Claude Code auto mode (GA 2026-07-10), Codex Auto-review, Cursor 3.6 Auto-review (2026-05-29). This is the main substitute for an "auto-approval engine". Cursor's own docs call its classifier non-deterministic and not a security boundary. That leaves room for a deterministic, portable layer.
3. **Regex-on-raw-text guards have a public bypass class.** Adversa AI disclosed "GuardFall" on 2026-06-30. The fix is to parse commands the way the shell does. Caro has partial unquoting (`destructive_unescaped` in `src/safety/mod.rs`), not full shell-semantic parsing.
4. **A vendor has proposed the engine-to-harness standard Caro would need.** Gen Digital's AARTS v0.1 (draft, 2026-03-05) defines host / adapter / security-engine roles. It has no named adopters yet. Gen's open-source `Sage` is the reference engine.
5. **License matters for a "community-maintained" rule DB.** dcg's license bars OpenAI, Anthropic and their affiliates, so it is not OSI open source and an AGPL project cannot absorb its rules. Sage ships rules under DRL 1.1. Project CodeGuard uses CC BY 4.0. Caro's AGPL-3.0 is OSI-approved but copyleft.
6. **Sandboxes are partners, not competitors.** Anthropic's own July 2026 containment write-up says classifiers "cannot guarantee" behavior and the environment must set the hard boundary.

Method: GitHub stats come from the GitHub API (search endpoint) on 2026-10-11. "Pushed" is the last push date. Product claims come from READMEs, docs and vendor posts fetched this session. Items marked **(unverified)** came only from search-result summaries or third-party/vendor comparison pages, not from a primary page I fetched.

## Closest competitors to Caro's cross-harness engine positioning (top 5, ranked)

Caro's claimed position: cross-agent, cross-harness, cross-model, community-maintained command-safety / auto-approval engine; deterministic regex rules with risk levels; local LLM; weekly CVE-derived rules; AGPL-3.0 Rust.

**Caveat on "Caro has" (updated 2026-10-13):** `caro guard` merged in #1513 on 2026-10-11 (`9516868`): a shadow-by-default PreToolUse adapter for Claude Code, Codex, Grok Build and OpenCode (ADR-020, spec 011). Caro still does not auto-approve; that role is positioning, not a shipped feature. The "Caro has" lists below only claim shipped items (regex patterns + risk levels, CVE patterns in `src/safety/cve_patterns.rs`, local LLM, NL-to-command generation) and the license.

**Substitute to watch first (not ranked, single-harness):** the harness-native auto-reviewers (Claude Code auto mode, Codex Auto-review, Cursor Auto-review). They do the "auto-approval" job for free, inside the harness. They are LLM classifiers, so they are not deterministic or auditable, and each covers one harness. Caro's opening is to be the deterministic, portable floor under them, or to export its rules into their native formats (Codex Starlark `prefix_rule`, Gemini TOML, Claude Code `permissions`, Cursor `permissions.json`).

### 1. dcg - Destructive Command Guard
- **Why closest:** Same form factor. Rust binary, deterministic rule packs, PreToolUse-style hooks, 17+ harnesses, largest community (6,139 stars in ~9 months).
- **Caro has, dcg lacks:** an OSI license that OpenAI and Anthropic can use (dcg's rider bars them); weekly CVE-derived rules; explicit risk levels on every match (dcg severity model not verified); a local LLM path; NL-to-command generation. dcg only blocks, so the auto-approve role is open (Caro does not ship it yet either).
- **dcg has, Caro lacks:** 50+ domain packs (cloud, k8s, DB, Terraform, CI/CD, DNS, payments); heredoc and inline-script scanning; SIMD sub-ms engine; one-line installers with signature checks; adapters for ~17 harnesses; allow-once codes; much larger user base.
- **Note:** Caro cannot import dcg rules or code. The rider adds restrictions that AGPL-3.0 forbids (not legal advice).

### 2. cc-safety-net
- **Why:** Cross-harness leader on reach (16 harnesses per its README on 2026-10-13), MIT, semantic command parsing, team-shareable policy folder, rule "rulebooks".
- **Caro has, it lacks:** Rust single binary (no Node runtime); CVE pipeline; risk levels; local LLM. Neither ships auto-approve.
- **It has, Caro lacks:** semantic unwrapping of wrappers and interpreter one-liners; secret / sensitive-file gating for file tools (not only shell); GUI with Standard/Strict/Paranoid presets; library API; broad harness installer (`npx cc-safety-net install` + `doctor`).

### 3. Gen Digital Sage + AARTS
- **Why:** Closest in strategy. A security vendor is open-sourcing a cross-harness engine (Allow/Ask/Deny), a community-contributable YAML threat-rule set under a rule-sharing license (DRL 1.1), and a vendor-neutral engine/host standard (AARTS). That is Caro's thesis with a large company behind it.
- **Caro has, it lacks:** fully offline by default (Sage calls reputation APIs); Rust; CVE pipeline; NL generation. Sage lists no Codex or Gemini CLI adapter (Claude Code, Cursor, VS Code, OpenClaw, OpenCode only), which leaves room; Caro ships no adapters yet.
- **It has, Caro lacks:** URL and package reputation; ML prompt-injection model; file-write and package-install gating; 300+ rules; brand trust (Norton/Avast); a draft standard that Caro would otherwise have to write.

### 4. HOL Guard
- **Why:** "Antivirus for AI agents" with 16 harnesses, Rust-evaluated declarative rules, local-first with optional cloud, and a curated advisory feed. Grew to 845 stars in ~6 months.
- **Caro has, it lacks:** CVE-derived command rules; risk levels per command; local LLM.
- **It has, Caro lacks:** MCP, package, plugin and skill coverage; secret detection; approvals dashboard and receipts; advisory database; more harness adapters.

### 5. Perplexity Numbat
- **Why:** Cross-agent (claimed 25 of 26 surfaces), YAML/CEL rules with multi-step sequence detection, opt-in pre-action blocking, Apache-2.0, backed by Perplexity. 1,106 stars in ~11 weeks.
- **Caro has, it lacks:** block-by-default command safety (Numbat ships monitor-only); shell-specific depth.
- **It has, Caro lacks:** sequence rules (e.g. secret read then `curl` egress); forensic reconstruction; endpoint fleet visibility; CEL rule language.

**Auto-approval niche (small but exact match to "auto-approval engine"):** Dippy (full bash parser, 243 stars, MIT) and safe-chains (Rust, 450+ commands at flag level, 14 stars). Both show that safe auto-approval needs flag-level command knowledge plus a real parser, not deny-regexes alone.

**Cross-cutting gap for Caro:** GuardFall shows that raw-text regex guards are bypassable. Caro already unquotes destructive commands with `shell_words` (`destructive_unescaped`, `src/safety/mod.rs`). It does not appear to parse full shell semantics (command substitution, `eval`, base64-to-shell pipes, variable indirection) **(based on a grep of `src/safety/`, not a full audit)**. Running the GuardFall examples and a Dippy/Parable-style parser corpus against Caro would quantify the gap.

## Partners, not competitors

1. **Containment layer (layer 2 under Caro's intent check):** Anthropic `srt`, nono, NVIDIA OpenShell, Docker Sandboxes, agentsh, Leash, container-use, smolvm. Anthropic's containment post says classifiers "cannot guarantee" behavior and the environment sets the hard boundary. GuardFall coverage says only a sandbox removes the risk. Caro's pitch should be "fewer prompts and clear explanations on top of a sandbox", not "instead of a sandbox".
2. **Engines that could consume Caro rules:** agentsh (`command_rules`), Microsoft AGT (has "command denylist enforcement" but no named shell rule pack; Caro already ran an AGT/agentmesh build spike per `.claude/rules/external-sdk-integration.md`, PR #1103), Leash (Cedar), Sponsio (contracts).
3. **Harness policy formats as export targets:** Codex execpolicy Starlark, Gemini CLI policy TOML, Claude Code permissions + hooks, Cursor `permissions.json`, AARTS security-engine interface. Exporting Caro's rule DB into these turns the harness-native features into distribution.
4. **Adjacent detectors (different threat, same hook):** GitGuardian ggshield AI hooks (secrets), Aikido safe-chain (package installs; 1,791 stars), pipelock (egress/MCP DLP), Lasso claude-hooks and LlamaFirewall PromptGuard (prompt injection in tool output), Snyk Agent Scan / AgentShield / cc-safe (config posture).
5. **Rule and test sources:** GTFOBins, LOLBAS, LOOBins (GPL-3.0; GPLv3 §13 allows combination with AGPLv3, confirm with counsel), Sigma (schema model), Atomic Red Team (test corpus), ATT&CK / ATLAS / OWASP ASI02-ASI05 (tags), CISA KEV + OSV (CVE pipeline feeds), GuardFall (adversarial tests).
6. **Commercial endpoint vendors as downstream consumers (recommendation, not evidence):** Pillar, Zenity, Noma, Palo Alto, Microsoft Defender, CrowdStrike, HiddenLayer all now sit on the same pre-tool hooks. A permissively licensed, versioned command-rule DB (like Sigma for SIEMs) is something they could consume. That would need the rules licensed separately from the AGPL engine.
