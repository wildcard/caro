## Key Research Findings

### Finding 1 — Azure AI Inference beta SDK retires 2026-08-26 (CRITICAL)

The `azure-ai-inference` Python/JS beta SDK is **deprecated** and will be retired
in 83 days. Teams still using it are on a countdown clock. ADR-018 targets the
stable OpenAI/v1 API only — no dependency on the deprecated SDK. Caro is
positioned as a clean migration target.

**Source**: Microsoft Learn endpoint documentation, updated 2026-02-27.

### Finding 2 — No Rust SDK for Azure Foundry

No official or well-maintained Rust SDK exists for Azure AI Foundry inference.
The "languages without a first-class SDK" path is explicitly documented as "call
the REST API directly." This confirms the `reqwest`-only approach is not a
workaround — it is the correct Rust integration pattern.

**Source**: Team 400 Azure AI consulting field guide, May 2026.

### Finding 3 — Three production failure modes, solved by design in ADR-018

| Failure mode | Frequency | ADR-018 solution |
|---|---|---|
| Hardcoded `api-version` drift | "Most common long-term break" | Named config field + `warn_if_stale_api_version()` |
| `Authorization: Bearer` vs `api-key` header confusion | "Hours lost, looks like a permission error" | Field named `api_key`; struct comment names the header explicitly |
| Deployment name ≠ model name | "Config working on Ollama silently broken on Azure" | Config field named `deployment_name`; `BackendInfo.model_name` echoes it |
